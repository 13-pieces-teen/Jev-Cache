# Jev-Cache 功能验收 · 2026-09-27

本轮基于更新后的悬浮窗、小面板和详情窗口，检查实际命令、Runtime、存储、原生宿主与 Edge 连接。结论：**本地核心功能已形成可运行的开发原型，真实 Edge 状态同步已接通；通用自动应用清理与可证明的内存收益尚未完成验收。** 不用界面完成度代替清理能力完成度。

## 本轮发现与修复

1. **助手窗口在运行，但 Edge 一直报不可用。** 实际捕获到 `AuthenticationError: digest received was wrong`；认证失败未被捕获，导致监听线程退出。安装时现为宿主写入明确的管道地址和助手凭据文件的真实路径，适应启动环境的路径重定向；错误认证后继续接收连接。未放宽身份验证，也未更改系统安全策略。
2. **只读文档几乎都被认作不可释放。** 核对 Python / Qt 当前文档 HTML 后，发现导航复选框、搜索提交按钮和 Qt 搜索框命中旧的“编辑页面”规则。现仅识别这些已知控件；未知表单、非空输入、可编辑内容、媒体和 iframe 仍保留。页面结构采样保存在本机 `artifacts/readonly-document-controls.json`。
3. **对象资格改变时，释放按钮可能不刷新。** 列表更新现包含允许动作、适配资格与说明；失去资格时及时禁用按钮。本地执行复核和扩展执行前复核继续存在。
4. **移除密钥后仍留有输入草稿和上传勾选。** 现在同时清空草稿、关闭上传选项；Runtime 清除保存的密钥并关闭自动模式，避免下一次保存重新带入。
5. **诊断消息可能被当成浏览器工作流。** `ping` 不再更新网页连接状态或取走待执行命令；连接成功必须有实际快照。

## 最后一项浏览器操作验收

本轮浏览器控制工具返回 `nodeRepl.fetch request failed`，无法完成真实页面操作。以下步骤保留为人工验收，不能以扩展模拟结果替代：

1. 运行最新 `dist/JevCache/JevCache.exe`；其他预览目录仍可能是较早构建，验证时只保留一个助手实例。
2. 在 Edge 扩展管理页重新加载 Jev-Cache，使更新后的页面探针生效；随后新开 [Python JSON 文档](https://docs.python.org/3/library/json.html)。
3. 等页面加载完成，切换到另一个 Edge 标签。保持测试页为后台页，不输入搜索内容。
4. 在助手“应用与网页”找到 `docs.python.org`，检查其支持释放，再点击“释放网页”。
5. 在“处理记录”确认实际完成；标签入口应继续存在。
6. 点击记录里的“重新打开”，确认原文档能重新加载。再观察内存记录；没有有效测量时，应显示无法确定，而非一个推测数字。

当前标签、用户保留项、带输入的页面和未知页面应拒绝释放。该人工流程无需开启云端摘要，也不验证 Jev 自动选择的效果。

- 真实浏览器释放／重新加载闭环和保护反例，持续运行及扩展更新后的可靠恢复。
- Jev 在真实候选上的判断质量、置信度校准、相对规则和个人记忆的增量。
- 有对照支持的持续净内存收益；未验证帧率或节省时间，不应展示为产品成果。
- 完整压力判断、跨重启记忆／Ghost 覆盖恢复、逐条解释与删除、升级分发和长期稳定性。
