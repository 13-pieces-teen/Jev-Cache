# Jev-Cache · 三分钟黑客松演示

面向其他 creator。核心表达：**用 Jev 给一个熟悉的桌面工具加入后台判断能力。你继续创作，它照看后台。**

演示重点：后台积累个人上下文 → 持续压力触发 → Jev 异步判断 → 受限动作 → 反馈进入下一轮。

## 0:00–0:20 · 开启自动

我用 Jev 做了一个后台内存助手，叫 Jev-Cache。写代码、查文档，一下午开了很多窗口。开启自动后，你继续创作，它观察状态，在需要时判断。这次就看 Jev 怎样进入日常软件。

画面：编辑器继续工作，桌面角落的悬浮窗从手动切换到自动。整段不点击“一键清理”。

## 0:20–0:50 · 积累上下文

后台先收集使用事件：哪些页面被访问，哪些内容被反复打开，上次清理后有没有重新打开或明确纠正。程序把这些信号整理起来，再结合用户补充的当前任务。需要判断时，只取出相关摘要交给 Jev。所以同样的一组网页，对不同用户、不同工作阶段，可以有不同的保留价值。这里的个性化，来自状态和反馈被持续积累、再次使用。

画面：直接观测、用户补充、历史反馈依次进入状态摘要。区分来源，不把推测画成已经观测到的事实。

## 0:50–1:20 · 按需唤醒

现在，内存出现持续压力。后台先确认它持续了一段时间，再把当前状态和相关记录交给 Jev，异步等待结果。用户还在写代码，界面继续响应，也不用再打开清理窗口。这里有一个分工：本地程序负责触发时机，Jev 负责这一次怎样选择。执行前还会检查目标是否刚刚被使用；压力缓解后，系统继续观察。

画面：示例压力持续，本地观察窗满足条件，随后出现一次后台判断。20 秒观察窗采用时间压缩；播放时长不代表模型延迟。

## 1:20–1:55 · 结合状态判断

看这两个文档。正在做界面时，很久没点的样式文档仍然重要；刚看过的线程文档，如果当前工作已经完成，可以稍后再用。等任务切到排查线程问题，下一轮的保留重点又会改变。我们把当前任务、使用记录和允许动作交给 Jev，得到任务关系、保留价值和动作选择。这些结构化判断进入执行计划，改变具体处理对象。

画面：同样两个页面、相同访问记录。先显示界面任务，1:38 切换为线程任务，展示下一轮的预期判断差异。三个分类问题各自读取同一份必要状态，不表示后一个已读取前一个答案。

## 1:55–2:30 · 记住反馈

完成动作后，助手继续观察结果，也记录用户的反馈。比如，你重新打开样式文档，并明确指出：调试线程时，这份资料也需要对照着看。程序先保护近期重开的对象，再保留这条反馈。下一次相似工作中，相关记录会重新进入 Jev 的输入。我们希望这样减少重复清理和反复加载；具体能改善多少，要用真实使用对照来验证。

画面：动作回执 → 重开与明确纠正 → 时间跳转至下一次同类工作 → 相关反馈进入输入。重开不自动等同于误清；即时冷却来自本地规则，历史在模型中的作用另行验证。

## 2:30–3:00 · 回到创作

Jev-Cache 想把这条闭环带进一个大家熟悉的小工具：后台持续提供状态，Jev 按需参与判断，反馈回到下一轮。对 creator 来说，我觉得值得探索的是，把软件里那些需要理解上下文的决定，接到模型上，再接回具体动作。你继续创作，它照看后台。把内存留给接下来要用的东西。

画面：持续观察 → 按需判断 → 反馈更新，回到产品标识与主张。保留约 3–5 秒收尾停顿，按个人语速调整口播。

## 与常见产品路径相比，要讲清楚的增量

| 维度 | 常见路径或对照 | Jev-Cache 的设计方向 |
| --- | --- | --- |
| 操作方式 | 用户主动整理；已有产品也提供自动休眠 | 用户开启后，由状态触发后台语义判断 |
| 对象选择 | 最近使用、频率、后台活动、保留名单等规则 | 在这些信号之上，加入当前任务语义与相关个人反馈 |
| 个性化 | 用户配置规则、白名单 | 使用事件和明确反馈形成可检索状态，供 Jev 再次判断 |
| 模型进入产品的位置 | 此处不对所有产品作泛化断言 | Jev 的结构化结果参与具体保留／释放计划 |

自动模式本身不是独占能力。重点是自动触发、状态组织、语义取舍和反馈闭环如何连起来。浏览器原生功能继续作为基线；不将系统自身的收益计为助手成果。

## 当前机制与后续探索

核对日期：2026-09-27。本次只读取实现与验证记录，没有重新运行清理或模型实验。

- 本地 `runtime.py` 已有后台采样、使用事件统计、相关 Ghost／feedback 检索、异步请求和执行前检查。
- 当前自动条件为内存使用率达到开发阈值并持续 20 秒、满足调用间隔等条件。触发调度由本地实现，Jev 不负责采样或通用操作系统调度。
- `provider.py` 把当前活动、候选对象、近期使用、相关记忆与允许动作整理为状态，使用有限 Choice 问题。
- 当前任务文本由用户补充；自动推断活动分组、自然语言习惯解释与更广泛的任务理解是可探索方向，不能当成已验收能力。
- 明确偏好与冷却属于本地保护。要证明 Jev 利用个人信息产生增量，应在同样状态、候选与动作能力下比较有无相关历史，确认实际输出与结果变化。
- 真实 SDK 连接和合成请求已有记录；真实清理收益、模型判断质量、个性化增量尚未完成验收。

本 HTML 中全部状态、判断、回执与时间由预置剧本驱动，没有调用真实 Jev，也没有操作电脑。正式演示若接入真实回放，应以对应请求、返回、动作回执与观测替换，保留来源标签。
